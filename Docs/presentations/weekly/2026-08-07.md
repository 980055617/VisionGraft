# 週次進捗: 2026-08-07（8/1〜8/7 の作業）

## 今週の主な実装

- **カット（shot）境界でモデルのスケールをリセットする実装** ← 今週のメイン
  - **症状**: カットが切り替わってもモデルの大きさが変わらず、前のカットのサイズのまま貼り付いて極端な見た目になる
  - **原因**: Human / Animal の表示スケールは `GetOrLockModelLocalScale` が trackId ごとに初回フレームで確定してロックし続ける。解除点が prefab 差し替え時と VR 内モデル変更時しかなく、カット境界が含まれていなかった。ロック自体は必要な設計（外すと bbox のブレでモデルが毎フレーム伸縮する）で、問題は解除点のほう
  - **bundle 側は既に対応済みだった**: `manifest.json` に `shots`（`[[start, end), ...]`）と `shot_boundary_policy` があり、`unity_guidance` が「同じ trackId でも shot をまたいで position/scale を補間・スプリングさせず、新しい shot の先頭フレームの anchor へスナップせよ」と明示していた。実データは `bundle_animal.svb` = 15 shot、`bundle_human.svb` = 1 shot、旧 `bundle.svb` / `bundle_old.svb` = フィールドなし
  - **実装**: `ShotBoundaries.cs`（`shots` を開始フレーム配列に正規化し、フレーム → shot index を二分探索で解決）と `StreamingStereoVideoPlayer.ShotBoundary.partial.cs`（`DisplayModelTick` で shot index の変化を検出し、track ごとの持ち越し状態をリセット）を新規追加
  - `JsonUtility` は `[[0, 258], [258, 338], ...]` のような入れ子配列を扱えないため、`shots` だけ生 JSON から `MiniJson` で読む構成にした（`ManifestData` には載せない）
  - リセット対象は「前フレームからの連続性を前提にした状態」のみ: スケールロック、ジョイント/root yaw の平滑化、Animal の OneEuro フィルタと SMAL 回転平滑化、SMPL 回転と root 位置・深度の平滑化、bbox 下端合わせのホールド、Human-Other の接触オフセット
  - 逆にリグのボーン解決結果、`rootYawFix`（実データから一度だけ決めてセッション中保持する向き判定）、参照姿勢、骨長キャッシュ（root 相対の実寸なのでカメラ距離に依存しない）は保持する
  - シークも shot index の変化として扱われる。同一 shot 内へのシークはカメラが連続しているためリセットしない
  - **後方互換**: `shots` を持たない旧 bundle は `ShotBoundaries.Empty` になり全編 1 shot 扱い = 従来どおりの挙動
  - 詳細は [bundle-placement.md](../../bundle-placement.md) の「カット（shot 境界）でスケールと平滑化をリセットする」に記録

- **被験者実験フローの実装**（新規シーン構成）
  - **実験デザイン**: 3 動画（Human / Animal / Train）× 2 条件（3D モデル置換あり／ステレオ動画のみ）= 6 試行。群 A は「置換なし 3 本 → 置換あり 3 本」、群 B はその逆でブロック順を相殺。動画順は 3! = 6 パターンを番号指定（前半・後半とも同じ順序）。群 2 × 順序 6 = 12 通りの割り付け
  - **なぜ新シーンにしたか**: `StreamingStereoVideoPlayer` の `Start()` が一度きりの coroutine で、2 本目の bundle に差し替える経路がない。モデルインスタンス・プロキシ・interactive motion の状態を安全に捨てる手段がないため、**試行 = シーンのロード／アンロード**にした。状態リークが原理的に起きず、プレイヤー本体のライフサイクルに手を入れずに済む
  - **既存機能がそのまま条件になった**: 「置換なし」条件は既存の normal mode（`source/pre_removal_stereo_video.mp4` = 除去前のオリジナル映像）をそのまま使う。ここに `video.mp4`（検出オブジェクトを消した除去済み映像）を使うと「穴の空いた映像」との比較になり対照条件が成立しない
  - **1 箇所だけ既存実装では足りなかった**: `SetNormalMode()` は「再生中に切り替える」実装で、試行開始時に呼ぶと切り替わるまでの数フレームだけ置換モデルが見えてしまう。`Prepare` する url そのものを最初から選ぶ経路（`ResolveInitialNormalMode`）を追加した
  - **ループ再生は既存のまま使えた**: `ConfigureForApiPlayback` が `isLooping = true` を設定済みだったので、「被験者が納得するまで 2, 3 周見てよい」という要件を改修なしで満たせた。何周見たかは試行ログに記録
  - **アクティブシーンの切り替えが必須だった**: プレイヤーが実行時に生成するモデルインスタンスと UI ルートは親を持たない root オブジェクトなので、Additive ロード直後に `SetActiveScene(TrialScene)` しないと生成物がベースシーン側に積み上がり、次の試行に前の試行のモデルが残る

  - プレイヤー側の変更は no-op 可能な static sink（`ExperimentLog`）経由のフック数行に留めた。実験を行わない通常シーンの挙動は変えていない

## 深度（anchor_z）の調査

- **`z01` は disparity 系と確定**（生成側の調査）。`depth.npz` は「近い=大きい / 遠い=小さい」の視差規約で、コード上は "depth" と呼ばれているが metric depth ではない。`disparity ∝ 1/depth` の逆数変換がパイプラインに無い
  - → Unity の `DecodeAnchorDepthMetersFromBundle` は `z01` に線形だが、**本来は反比例にすべき**（未修正）

- **チャンク間ドリフトを特定し、再生成で解消**
  - 症状: `z01` が実距離とまったく相関しない（全体 R² = 0.0037）
  - 原因: `--depth-chunk-size=140`（overlap 25）で 19 チャンクに分割され、`_fit_depth_affine` のアフィン係数誤差がチェーン式に蓄積
  - **境界では不連続が出ない**（`|Δz01|` 比 1.05 倍）ため気づきにくい。チャンク内 R²（max 0.93）と全体 R²（0.004）の比較で検出
  - 生成側でチャンク分割を見直し再生成 → **全体 R² = 0.1657（45 倍改善）**、境界の不連続も解消

- **配置の実測基盤を整備し、素の配置を検算した**
  - 推測で修正案を出す段階から脱するため、配置したモデルを画面へ再投影して `meta.bin` の bbox と直接比較する計測（`[PLACE]` / `[BONELEN]`）と、`bundle_human.svb` を実際に再生する `PlacementMeasurementTests` を追加
  - **ボール（Else）は完璧**: `sizeRatio` が全 70 サンプルで 1.000、位置ずれ 0.0 px。毎フレーム bbox からスケールを計算し直しているため
  - **Human は立位なら正しい**（1.02〜1.05）が、**座位・仰向けで縦に 1.5 倍はみ出す**。下端は合っていて上端だけが飛び出す
  - 原因として 7 つの仮説を実測で消去（スケールの決め方 / スケール固定 / 下端合わせ / `HumanSmplRotationAlpha` / 時間平滑化 / AABB の過大評価 / 体型差）。詳細は [smpl-retargeting.md](../../smpl-retargeting.md)
  - **体型差は逆方向だった**: Unity モデルの脚は映像より 9.3% *短い*。「脚が長いからはみ出す」という仮説は棄却。SMPL `betas` を反映する案（骨長の実行時調整）は、この結果により**効果が見込めないため中止**
  - 残る原因は FK の姿勢再現度（関節を折りたたむ角度が浅い）。未調査

- **`Else: 8 prefab` 問題を修正**
  - `Resources/Models/Else/Sources/DieselLocomotive.glb` が「大文字始まり」フィルタを通過して 8 件になっていた（本来 7 件）
  - フィルタを「2 桁ゼロ埋め番号 + `_`」に変更（`IsIndexedPrefabName`）。あわせて `Resources.LoadAll` の戻り順が保証されない問題に対処するため名前順ソートを追加し、`selectedElseIndex` / `trackModelIndices` の index を安定させた

## 発表で強調するポイント

- **「Unity 側に情報がない」と思っていたものが、実は bundle に既にあった**。`manifest.json` の `shot_boundary_policy` は Unity 側の実装指針（`unity_guidance`）まで含めて書かれており、Python 側と Unity 側の分業がフォーマットの中で明文化されている好例
- カットは「モデルが動いた」のではなく「カメラが切り替わった」。同じ trackId でも見かけサイズが変わるのは正当な変化で、平滑化して追従させるべきではない。**平滑化してよい変化と、スナップすべき変化を区別する**のがこの修正の本質
- スケールをロックする設計自体は正しかった（外すと bbox のブレで伸縮する）。バグは「ロックしていたこと」ではなく「解除点が足りなかったこと」
- **実験フローで新しく作ったものは意外と少ない**。「置換なし」条件は既存の normal mode、「何周でも見られる」はループ再生設定、条件切り替えの封じ込めは既存ボタン 1 つの非生成。作り込んだのは提示順の割り付けとログで、再生系は既存機能の組み替えで足りた
- **対照条件の取り違えが最大の落とし穴**。bundle には除去前と除去後の 2 本の動画が入っており、置換なし条件に除去後（`video.mp4`）を使うと「人や動物が消えて穴が空いた映像」を見せることになる。テストでも「StereoOnly のときだけ normal mode になること」を明示的に固定した

## 残課題

- **実機での確認が未実施**: 15 shot ある `bundle_animal.svb` でカット切り替え時の見た目を確認する必要がある。ログに `[Shot] boundary crossed. frame=... shotIndex=...` を出しているので、カットのタイミングと実際の切り替わりが一致しているかを合わせて確認する
- **interactive motion はリセット対象に含めていない**: カット中にインタラクティブモーションが再生されている場合の扱いは未定（継続すべきか中断すべきか）。仕様判断が必要
- **shots のレンジに隙間がある bundle** は、隙間のフレームを直前 shot の続きとして扱う（余計なリセットを避けるため）。現状の bundle はすべて隙間なしなので実害はない
- **Human の姿勢再現度**（今週の到達点）: 座位・仰向けでモデルが縦に 1.5 倍はみ出す。スケール・下端合わせ・平滑化・体型差など 7 つの仮説を実測で消去済みで、残るのは **FK の計算そのもの**（回転の適用式・座標変換・関節マッピング）。骨長が 9% 短いのに縦幅が 1.33 倍になる = 関節を折りたたむ角度が浅い、という状態。[smpl-retargeting.md](../../smpl-retargeting.md) の FK 公式に踏み込む必要がある
- **接触補正の位置精度**: 飛びは止まったが Other が正しい位置に来ない。ただし**ボール側の配置は完璧**（`sizeRatio` 1.000）と実測で判明したので、これは Human の姿勢再現度が直れば連動して改善する見込み。接触補正そのものの調整は Human 側が直ってから
- **深度変換式の反比例化**: disparity と確定したので理屈上は正しい修正。ただし全体 R² = 0.166 なので効果は限定的
- **`jointsWorld` のスケール未適用**（7/30 から継続）: `AlignHumanoidFeetYToSmplAnkles` が機能していない。打ち消しを解除してはいけない点に注意（[smpl-retargeting.md](../../smpl-retargeting.md)）
- **`Else: 8 prefab` 問題**: `Resources/Models/Else/Sources/DieselLocomotive.glb` が大文字始まりのため runtime のフィルタ（`IsPrefabNameStart`）を通過している。`Resources.LoadAll` の順序は保証されないため `trackModelIndices` の index ズレのリスクがある
- 7/31 からの継続課題（`updateWhenOffscreen = true` の副作用の実機確認、CC-BY-4.0 モデルのクレジット表示）
- **実験フローの実機確認が未実施**: シーン生成メニューの実行、6 試行の通し、ログの adb 回収までを一度通す必要がある。特に試行ごとの bundle 展開時間（`bundle_human.svb` は 155MB）が実験の進行として許容できるかを確認する
- **モデル変更を被験者に許可したことによる交絡**: 置換あり条件で見るモデルが参加者ごとに変わる。`operations.csv` に prefab 名まで記録して分析時に統制できるようにしたが、統制しきれないと判断した場合はモデルピッカーも非生成にする
- **試行の終了操作**: 現状は被験者自身が「視聴を終了」を押す方式（Quest 単体では実験者に入力手段がないため）。実験者側で制御したい場合は方式の変更が必要
