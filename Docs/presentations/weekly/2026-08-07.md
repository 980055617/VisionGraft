# 週次進捗: 2026-08-07（8/1〜8/7 の作業）

## 今週の主な実装

- **カット（shot）境界でモデルのスケールをリセットする実装** ← 今週のメイン
  - **症状**: カットが切り替わってもモデルの大きさが変わらず、前のカットのサイズのまま貼り付いて極端な見た目になる
  - **原因**: Human / Animal の表示スケールは `GetOrLockModelLocalScale` が trackId ごとに初回フレームで確定してロックし続ける。解除点が prefab 差し替え時と VR 内モデル変更時しかなく、カット境界が含まれていなかった。ロック自体は必要な設計（外すと bbox のブレでモデルが毎フレーム伸縮する）で、問題は解除点のほう
  - **bundle 側は既に対応済みだった**: `manifest.json` に `shots`（`[[start, end), ...]`）と `shot_boundary_policy` があり、`unity_guidance` が「同じ trackId でも shot をまたいで position/scale を補間・スプリングさせず、新しい shot の先頭フレームの anchor へスナップせよ」と明示していた。実データは `bundle_animal.svb` = 15 shot、`bundle_human.svb` = 1 shot、旧 `bundle.svb` / `bundle_old.svb` = フィールドなし
  - **実装**: `ShotBoundaries.cs`（`shots` を開始フレーム配列に正規化し、フレーム → shot index を二分探索で解決）と `StreamingStereoVideoPlayer.ShotBoundary.partial.cs`（`DisplayModelTick` で shot index の変化を検出し、track ごとの持ち越し状態をリセット）を新規追加
  - `JsonUtility` は `[[0, 258], [258, 338], ...]` のような入れ子配列を扱えないため、`shots` だけ生 JSON から `MiniJson` で読む構成にした（`ManifestData` には載せない）
  - リセット対象は「前フレームからの連続性を前提にした状態」のみ: スケールロック、ジョイント/root yaw の平滑化、Animal の OneEuro フィルタと SMAL 回転平滑化、SMPL 回転と root 位置・深度の平滑化、bbox 下端合わせのホールド、Human-Other の接触オフセット
  - 逆にリグのボーン解決結果、`rootYawFix`（実データから一度だけ決めてセッション中保持する向き判定）、参照姿勢、骨長キャッシュ（root 相対の実寸なのでカメラ距離に依存しない）は保持する
  - シークも shot index の変化として扱われる。同一 shot 内へのシークはカメラが連続しているためリセットしない
  - **後方互換**: `shots` を持たない旧 bundle は `ShotBoundaries.Empty` になり全編 1 shot 扱い = 従来どおりの挙動
  - 詳細は [bundle-placement.md](../../bundle-placement.md) の「カット（shot 境界）でスケールと平滑化をリセットする」に記録

- **テスト**: `ShotBoundariesTests.cs`（14 ケース: 実 bundle 相当のデータ、shots なし、単一 shot、逆順・空レンジ・型不正の排除、未ソート、範囲外フレーム）と `ManifestLoaderTests.cs` への 3 ケース追加

## 発表で強調するポイント

- **「Unity 側に情報がない」と思っていたものが、実は bundle に既にあった**。`manifest.json` の `shot_boundary_policy` は Unity 側の実装指針（`unity_guidance`）まで含めて書かれており、Python 側と Unity 側の分業がフォーマットの中で明文化されている好例
- カットは「モデルが動いた」のではなく「カメラが切り替わった」。同じ trackId でも見かけサイズが変わるのは正当な変化で、平滑化して追従させるべきではない。**平滑化してよい変化と、スナップすべき変化を区別する**のがこの修正の本質
- スケールをロックする設計自体は正しかった（外すと bbox のブレで伸縮する）。バグは「ロックしていたこと」ではなく「解除点が足りなかったこと」

## 残課題

- **実機での確認が未実施**: 15 shot ある `bundle_animal.svb` でカット切り替え時の見た目を確認する必要がある。ログに `[Shot] boundary crossed. frame=... shotIndex=...` を出しているので、カットのタイミングと実際の切り替わりが一致しているかを合わせて確認する
- **interactive motion はリセット対象に含めていない**: カット中にインタラクティブモーションが再生されている場合の扱いは未定（継続すべきか中断すべきか）。仕様判断が必要
- **shots のレンジに隙間がある bundle** は、隙間のフレームを直前 shot の続きとして扱う（余計なリセットを避けるため）。現状の bundle はすべて隙間なしなので実害はない
