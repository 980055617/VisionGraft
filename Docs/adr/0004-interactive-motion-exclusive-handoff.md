# Interactive motion events take exclusive root/pose authority, with a fixed-duration handoff blend

The previous interactive motion implementation let pose tracking keep writing to the model's transform while an event (gesture clip, approach, animal preset) was also running, blended by weight. In practice the two kept fighting: a model pinned in place for a static gesture would still visibly drift toward the live tracked anchor, and the "in place" guarantee broke down. We decided that while an interactive motion event is active, normal pose tracking for that track is fully suspended — the event owns the root and pose 100% until it ends. Only at the end does a fixed-duration blend (independent of how far the live tracked anchor has drifted during the event) hand control back to tracking. Distance-proportional handoff speed was considered and rejected for v1 to keep the blend simple and predictable; a fixed duration was judged perceptually acceptable since typical drift during an event is small.

We also folded the existing animal frame-out behavior (filling in an offscreen position while a track is invisible, then rejoining tracking at frame-in) into the same state machine as the new static/dynamic interactive motion events, instead of keeping it as a separate parallel mechanism. Frame-out is modeled as a system-triggered dynamic animation: same walking-motion primitive and same exclusive-authority/handoff-blend rules as the randomly-triggered dynamic animation, but with no middle gesture phase and a destination resolved from the predicted frame-in position instead of the viewer. Both mechanisms were independently buggy and shared the same "root walks from A to B over time" shape, so unifying them fixes both at once instead of patching two parallel implementations.
