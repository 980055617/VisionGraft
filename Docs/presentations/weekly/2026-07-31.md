  - **bundle 側のデータは正しかった**: `meta.bin` の正規化深度 `z01` は 83.6% のフレームで「ボールが Human より手前」を正しく記録していた
  - **原因は Unity 側**: Else カテゴリだけ `ApplyMetaTarget` が `meta.bin` の anchor を捨てて `source/other_object_proxies.json` の値で上書きしていた。この sidecar の `cameraXyz` は `units="same_as_depth_npz"`、つまり 0=far/1=near の正規化深度でメートルではないため、そのまま world 座標に流すと前後関係が反転する。全 2156 フレームのうち **55.2% でボールが Human より奥**になっていた
  - 修正: proxy による位置・スケール上書きを廃止し、Else も Human/Animal と同じ `anchorZ` + bbox 経路に統一。sidecar 読み込みと `showOtherProxyBoxes` のデバッグ表示は debug 用途として残置
  - 詳細と数値は [bundle-placement.md](../../bundle-placement.md) の「NG パターン: `source/other_object_proxies.json` を配置に使う」に記録

- **「深度レンジの圧縮」仮説を実測で棄却**
  - 当初は「`PopoutRangeMeters = 0.35f` の圧縮で Human とボールの深度差が 1.6 cm しかなく、ボールが Human のメッシュに埋まる」と判断していたが、配置スケールを無視した誤りだった
  - 実測: Human の配置身長は median **0.305 m**（スクリーンの見た目サイズに合わせるためミニチュアになる）。ボール ↔ Human の 3D 距離は median **0.098 m**（身長比 0.41）で、内訳は高さ 9.0 cm が支配的、奥行き 1.6 cm は補助的
  - 胴体半径（身長 × 0.07）以内に入るフレームは **1.1%** のみ。しかもそれは実際に体に接触している瞬間（胸トラップ・ヘディング）なので物理的に自然
  - よって深度レンジの拡大は優先度を下げた。詳細は [bundle-placement.md](../../bundle-placement.md) の「深度レンジの圧縮は実害が小さい」に記録

- **座位シーンで Human モデルが浮くバグを修正**
  - `bundle_human.svb` の座るシーン（最長は frame 373-799 = 12.4〜26.6 秒の 14.2 秒間。SMPL の膝・股関節角度から検出すると全体の **26.4%** が座位）で、モデルが地面ではなく浮いて座っていた
  - 原因は bottom alignment が 2 段階とも rest pose（立ちポーズ）基準だったこと。(1) `baseBottomOffsetLocal` が `ReplaceableModel.Awake` の固定値（root から足裏 ≈ 身長の 53%）、(2) FK 後の `FitDisplayedModelToBBox` 補正が読む `renderer.bounds` が `m_UpdateWhenOffscreen: 0` のためスキニング変形を反映せず、補正量がほぼ 0 になっていた
  - 浮き量の概算は 4.5〜7.3 cm（座位の配置身長 0.16 m の 28〜45%）
  - 修正: `TrackInstanceFactory.Create` で全 `SkinnedMeshRenderer` の `updateWhenOffscreen = true` を設定し、既存の補正パスを機能させた
  - 詳細は [bundle-placement.md](../../bundle-placement.md) の「NG パターン: rest pose 基準の bottom alignment で座位モデルが浮く」に記録

## 発表で強調するポイント

- `source/*` を runtime 配置に使わないという鉄則は方針の問題ではなく、**単位系が runtime と揃っていない**という実害を伴う。しかも sidecar の値域（0.26〜0.91）が偶然 runtime の配置レンジ（0.69〜0.78 m）と近いため、「それらしく配置されるが前後だけ壊れる」という気づきにくい壊れ方をしていた
- 「bundle が悪いのか Unity が悪いのか」は `meta.bin` を直接パースして両者の深度を全フレーム比較することで切り分けた
- **1 次元（深度）だけを見た判断は誤る**。「足でボールを扱う」「胸でストップする」シーンを思い浮かべれば、ボールと人物は同じ高さにいないと気づける。3D 距離で測り直したら、2 体を離しているのは奥行きではなく高さだった

## 残課題

- **深度順序の反転 16.4%**: 奥行き差が 1.6 cm しかないため bundle 側の depth 推定ノイズで簡単に逆転する。ただし高さで 9 cm 離れているので視覚的な破綻は軽微
- **立体感の乏しさ**: 1 m 先で 1.6 cm の奥行き差は両眼視差の角度差が 0.1 度未満でほぼ知覚できない。「ボールが手前にある」感覚は出ない。物理的に正しい距離が必要になった時点で、bundle 側の metric depth 対応（`manifest.json` に depth のスケール・シフト係数を載せる）が本筋
- **接触シーンの整合**（今後の本題）: 「足でボールを扱う」「胸でストップする」ように見えるかは深度レンジではなく **Human の SMPL 姿勢追従の精度とボール anchor の精度**の問題。将来のインタラクション実装（手足とボールの接触）でここが焦点になる
- **`updateWhenOffscreen = true` の副作用**（要実機確認）: (1) 立位の見え方も変わり得る（rest pose 基準の `baseBottomOffsetLocal` は実際の足裏より下を指しているため、bounds が正確になると立位でも補正が入る）、(2) `DisplayModelTick` は `Update()` から呼ばれるため bounds が 1 フレーム前の姿勢になり得る、(3) bounds が毎フレーム変わることによるジッター。ジッターが出た場合は補正結果に EMA 平滑化を入れる
- **座位の浮きが残る場合の次案**: `HumanoidRigCache` から足ボーン（LeftFoot / RightFoot / Toes）の world 位置を取り、その最下点を bbox 下端に合わせる。bounds に依存せずジッターも出にくいが、床座りで尻が最下点になるケースは足ボーンでは捉えられない
- CC-BY-4.0 モデル（ディーゼル機関車）のクレジット表示が未対応（7/17 から継続）
