## 実機テストで見つかった不具合（8/7）

- **Display（normal mode）を押すと黒画面になる**
  - **原因**: `source/pre_removal_stereo_video.mp4` が **MPEG-4 Part 2（mp4v / Simple Profile）** で書かれており、Quest の MediaCodec がデコードできない。`video.mp4` は h264/libx264 なので、**同じ bundle の中で除去前と除去後で映像コーデックが違っていた**。解像度 2560x640 / 30fps / 2167 フレーム / AAC 128kbps / 尺 72.23s は完全に同一で、差は映像コーデックだけ。`bundle` / `bundle_human` / `bundle_animal` / `bundle_train` の 4 本すべて該当
  - **黒画面になる仕組み**: 再生は `renderMode = APIOnly` + `frameReady` でスクリーンのマテリアルにテクスチャを貼る構成。デコードできないと例外ではなく「`frameReady` が来ない = テクスチャが更新されない」として現れるので、UI もログも正常なまま画面だけ黒くなる
  - **`VideoPlayer.errorReceived` を誰も購読していなかった**ため完全に無言だった。エラーログとモード切替ログ（`[Mode] switch ...` / `[Mode] prepared ...`）を追加して、次からは logcat で切り分けられるようにした
  - **対処は生成側**: pre_removal も `video.mp4` と同じ libx264 設定で書き出す。Unity 側でトランスコードやフォールバックはしない（[adr/0003](../../adr/0003-normal-mode-playback-video.md) にコーデック要件として記録）
  - 出荷前チェック: `ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,codec_tag_string -of csv=p=0 <video>` → `h264,avc1` なら OK、`mpeg4,mp4v` は NG

- **Models パネルにコントローラのレイが当たらない**
  - **原因**: ModelPicker パネルだけ `runtimeControlsPrefab`（`Assets/Prefabs/CanvasWithInteractionRay.prefab`、子に ISDK の `RayInteractable` / `PointableCanvas` / `Surface`）を使わず、素の Canvas + `GraphicRaycaster` で生成していた。Meta Interaction SDK のレイは `RayInteractable` の無い Canvas には当たらないため、**同じバーから開く Settings は反応して Models だけ無反応**という症状になっていた

## 実機テストから派生した 2 件の修正（8/7）

- **モデル変更時のスケール基準を shot 先頭フレームに揃えた**
  - **症状**: VR 内でモデルを差し替えると、その瞬間のフレームの bbox で大きさが決まる。同じ shot の同じ track を見ていても、変えたタイミングで表示サイズが変わる
  - **原因**: スケールのロックが外れる契機が 2 つあり、基準フレームが揃っていなかった。shot 境界では `Clear()` → 新 shot の**先頭フレーム**でロック、モデル変更では `Remove(trackId)` → **変更した瞬間のフレーム**でロック。`GetOrLockModelLocalScale` は「ロックが無ければ渡された値をそのまま焼き付ける」だけなので、解除した時点のフレームがそのまま基準になっていた
  - **実装**: `TryResolveShotStartScaleReference`。ロックが無い track についてのみ現在の shot の先頭フレームを読み直し、その bbox でスケールを計算する。ロック済みなら早期 return するので毎フレーム meta.bin を引くことはない。shot 途中から登場して先頭フレームに居ない track は従来どおり現在フレームでロックする
  - **副次的に、シークでも基準が揃うようになった**。同じ shot の中央へ飛んだ場合も shot 先頭が基準になる
  - **実験の交絡が 1 つ減った**: 変更タイミングが違う参加者どうしで同じ track が別サイズに見える状態だった。`operations.csv` には prefab 名しか残らないので、後から統制できない類の交絡だった

- **実機で「置き換える対象」を選べるようにした**
  - **症状の実態**: パネルの案内は "Point at a displayed person or animal, then press Change Model." だが、Quest では指しても何も起きず、対象は常に `displayTrackIds[0]`（TestScene では track 0）に固定されていた
  - **原因**: 対象選択の入口 `PointerClickInput.TryReadPrimaryClickPosition` が **`Mouse.current` しか読んでいなかった**。マウスのない実機では `null` で即 false になり、`TrySelectDisplayTrackFromPick`（anchor から 80px 以内の最近傍）が一度も呼ばれない。Editor でのみ動く機能だった
  - **実装**: `TryPick` を「レイの供給元」から分離し、マウスが無ければコントローラの aim pose（OpenXR の `PointerPosition` / `PointerRotation`、無ければ `devicePosition`）からレイを作る。UV → ピクセル変換以降は既存経路をそのまま使う
  - **座標変換をシーン階層に依存させなかった**: XR デバイスが返す姿勢は tracking origin ローカル。`OVRCameraRig/TrackingSpace` のような親子関係を当てにすると rig 構成を変えたときに黙って壊れるので、**HMD のローカル姿勢とシーン上の head Transform の world 姿勢の差分**から変換を作った（`RuntimeXrRayPick.ResolveWorldRay`）。純粋関数なのでテストで固定できる
  - **`displayTrackIds` の上書きをやめた**: 従来の pick は選んだ track を `displayTrackIds` にも代入していた。これは「表示する track の絞り込み」なので、実機で有効化すると**人を指しただけでボールが消える**ことになる。対象選択には `runtimeModelPickerTrackId`（優先順位 1 位）の更新だけで足りる
  - パネルを開いている間は pick を止める（UI 操作のトリガーで背後のスクリーンを拾わないため）

- **ヒット点 → 画素座標の変換が壊れていたのを修正**（上の機能を有効にする過程で判明）
  - `TryRaycastScreenPlane` は `InverseTransformPoint` の結果を **`localScale` で割って** UV にしていた。`InverseTransformPoint` は localScale を打ち消すので local は既にメッシュ座標（Quad なら ±0.5）であり、もう一度割ると**スクリーンを大きくするほど UV がずれる**。範囲判定も `localScale * 0.5` と比較していたため、スクリーンの外を指しても素通ししていた
  - さらに `TryPick` 側が `v = (1 - uv.y) * (eye_h - 1)` と**上下を反転**していた。`uv.y` は既に上原点なので、反転した結果 80px の最近傍判定にまず当たらない
  - `EyePixelToWorldOnScreen`（`v = (0.5 - local.y) * eyeH`）の正確な逆変換になるよう、メッシュ bounds で正規化する形に直した。**Editor のマウスクリックでもこの経路は正しく動いていなかった**ことになる

- **テスト**: `RuntimeXrRayPickTests.cs`（7 ケース。押下エッジ、rig が原点／移動回転している場合の world 変換、HMD 自身が向きを変えている場合に差分だけが効くこと）

## 追加した Renderpeople で手足が破綻 — FK 公式のリグ依存が判明（8/7）

`16_Male_Eric` を `bundle_human.svb` で再生すると手足が大きく崩れた。**リグ側の作業がゼロで済んだこと自体は正しかったが、
姿勢追従の側が特定リグの性質に依存していた**。

- **実機なしで原因を確定できた**: `bundle_human.svb` の `meta.bin` から実 body_pose を取り出し、2 つのリグに同じ θ を
  入れて各ボーンの長軸 world 方向を比較する検証をオフラインで組んだ。ログ取りのために Quest を回す前に決着した
- **真因は FK 公式が `bindRotWorld ≈ identity` のリグでしか成立しないこと**。現行の
  `tw[j] = parentTW * bindRotLocal[j] * θ[j]` は展開すると `G * bindRotWorld[j] * θ[j]` で、SMPL の body_pose を
  **ボーンのローカル軸**で掛けている。SMPL の θ は canonical フレーム（world 軸平行）の回転なので、
  正しくは `Θ[j] * bindRotWorld[j]` と左から掛ける
- **既存 14 体は偶然成立していただけ**。npc_casual_set は胴・肩・腕の bindRotWorld が identity から 0〜20° しか
  離れておらず誤差が出ない。Renderpeople は**全ボーンが 90〜120°** 乖離しているので破綻する
- **同じ θ を 2 リグに入れたときの食い違いは現行公式で平均 58.6°、左掛けに直すと全ボーンで 0.0°**（完全にリグ非依存）
- **手足が目立つ理由**: 後段の AimAt（`TryApplySmplArmSegment`）が四肢の**方向**しか直さないため。roll（ねじれ）と、
  AimAt を持たない Shoulder・Toes・胴の誤差が残り、末端ほど累積して見える
- **独立した第 2 の問題**: Renderpeople の twist ボーン 8 本（`upperarm_twist_l/r` 等）は `HumanBodyBones` に対応が
  なく Avatar に登録できないため、FK でも AimAt でも書き換えられず静止する。ひねりで手首・足首のメッシュが破綻する。
  **Animator を有効に戻しても直らない**（`armTwist` は UpperArm/LowerArm 間の配分パラメータで、追加ボーンを駆動しない）
- 実測値と否定した仮説は [smpl-retargeting.md](../../smpl-retargeting.md) の調査ログ 2026-08-07

## 深度（anchor_z）の調査

- **`z01` は disparity 系と確定**（生成側の調査）。`depth.npz` は「近い=大きい / 遠い=小さい」の視差規約で、コード上は "depth" と呼ばれているが metric depth ではない。`disparity ∝ 1/depth` の逆数変換がパイプラインに無い
  - → Unity の `DecodeAnchorDepthMetersFromBundle` は `z01` に線形だが、**本来は反比例にすべき**（未修正）

- **`anchor_z` の符号が bundle 世代で逆になった → Unity 側で吸収**（8/6、生成側と往復して解決）
  - **発端**: `bundle_human.svb` でボールが人物の奥に回り込む。実測すると**ボールが人より手前になるフレームが 16.4% しかない**（ボール遊びの動画なので大半のフレームで手前のはず）
  - **原因**: 生成側が深度規約を統一し、`manifest.json` に `depth_policy` を追加。これに伴い `meta.bin` の `anchor_z` が `larger = nearer` → **`larger = farther`** に反転した。Unity 側は旧規約のままだったため前後関係が反転していた
  - **生成側の対応漏れも見つかった**: 新設された `animal_camera_root` 経路（AniMer の root を placement anchor に使う）だけ反転が入っておらず、**同じ日に生成された human と animal で符号が逆**という状態だった。原因は `project_animal_keypoints_to_camera.py` の反転修正が未コミットのまま、その修正前に作られた `keypoints3d.json` が使われていたこと
  - **Unity 側の実装**: `manifest.json` の `depth_policy` の**有無**で向きを判定する（`IsAnchorDepthLargerMeansFarther()`）。値そのものから向きを推定しない（深度が中央付近に固まっている bundle では推定が成立しないため）。旧 bundle（`bundle_train.svb` 等）はそのまま再生できる
  - **結果**: ボールが人より手前のフレームが **16.4% → 83.0%**。実機でも違和感なしを確認

- **符号の判定手法で遠回りした（再発防止のため記録）**
  - 最初に使った「`rawAnchor.z` と sidecar の `depthStats.median` の照合」は、`animal_camera_root` 経路では `median` が `anchor_z` のコピーであるため**同語反復**で、証拠にならなかった
  - 生成側が出した「bundle の値と `keypoints3d.json` の値が完全一致する」という反証も、同じ理由で**搬送の証明であって規約の証明ではない**。反転漏れ・二重反転のどちらでも一致は起こる
  - 生成側が使った「`z` と bbox 面積の相関」は、`edgeTouch`（bbox が画面端で切れる。animal は 80.5%）と `held_previous_high_conf`（z 固定のまま bbox だけ動く。22.6%）を除外しないと符号がショットごとにバラつき、判定不能になっていた
  - **決着した方法**: ①除外条件を付けたうえで、**符号が既知の `bundle_human.svb` で手法を較正**してから animal に適用（human で負が出る手法で animal だけ 4 ショット全て正）→ ②生成側が `depth.npz` を anchor の `(u,v)` で直接サンプルして照合 → 「未反転」が確定
  - 修正後は animal の相関が **+0.628 → -0.591** と、**絶対値をほぼ保ったまま符号だけ反転**（各ショットも +0.511→-0.512 のように対応）。反転が正しく 1 回だけ効いたことの確認になった

- **`SpineBodyPoseScale` を 0.25 → 1.0 に修正**（座位・仰向けの縦はみ出しの真因）
  - 「SMPL が前傾を過大推定する」という理由で脊椎（joint 3 / 6）の body_pose を 25% に減衰していたが、実測すると**曲げの 75% を捨てており**、座位・仰向けで上半身が起き上がったままになっていた
  - 減衰なしにすると Hips-Neck-Head の角度が `meta.bin` の期待値と -15〜+4° まで一致し、投影高さ / bbox 高さが frame600 で **1.334 → 0.962** に改善
  - 測定定義の誤りで一度遠回りした: Unity の Hips-Neck-Head に対し `meta.bin` 側で `nose`(0) を使っていたため 40° のずれに見えていた。正しい対応は **`head_h36m`(43)**

- **チャンク間ドリフトを特定し、再生成で解消**
  - 症状: `z01` が実距離とまったく相関しない（全体 R² = 0.0037）
  - 原因: `--depth-chunk-size=140`（overlap 25）で 19 チャンクに分割され、`_fit_depth_affine` のアフィン係数誤差がチェーン式に蓄積
  - **境界では不連続が出ない**（`|Δz01|` 比 1.05 倍）ため気づきにくい。チャンク内 R²（max 0.93）と全体 R²（0.004）の比較で検出
  - 生成側でチャンク分割を見直し再生成 → **全体 R² = 0.1657（45 倍改善）**、境界の不連続も解消

- **配置の実測基盤を整備し、素の配置を検算した**
  - 推測で修正案を出す段階から脱するため、配置したモデルを画面へ再投影して `meta.bin` の bbox と直接比較する計測（`[PLACE]` / `[BONELEN]`）と、`bundle_human.svb` を実際に再生する `PlacementMeasurementTests` を追加
  - **ボール（Else）は完璧**: `sizeRatio` が全 70 サンプルで 1.000、位置ずれ 0.0 px。毎フレーム bbox からスケールを計算し直しているため
  - **Human は立位なら正しい**（1.02〜1.05）が、**座位・仰向けで縦に 1.5 倍はみ出す**。下端は合っていて上端だけが飛び出す
  - 原因として 7 つの仮説を実測で消去（スケールの決め方 / スケール固定 / 下端合わせ / `HumanSmplRotationAlpha` / 時間平滑化 / AABB の過大評価 / 体型差）。詳細は [smpl-retargeting.md](../../smpl-retargeting.md)
  - **体型差は逆方向だった**: Unity モデルの脚は映像より 9.3% *短い*。「脚が長いからはみ出す」という仮説は棄却。SMPL `betas` を反映する案（骨長の実行時調整）は、この結果により**効果が見込めないため中止**
  - 残る原因は FK の姿勢再現度（関節を折りたたむ角度が浅い）。未調査

- **`Else: 8 prefab` 問題を修正**
  - `Resources/Models/Else/Sources/DieselLocomotive.glb` が「大文字始まり」フィルタを通過して 8 件になっていた（本来 7 件）
  - フィルタを「2 桁ゼロ埋め番号 + `_`」に変更（`IsIndexedPrefabName`）。あわせて `Resources.LoadAll` の戻り順が保証されない問題に対処するため名前順ソートを追加し、`selectedElseIndex` / `trackModelIndices` の index を安定させた

- **`SampleScene` → `TestScene` のリネームにコードを追従**
  - 統合テスト 3 本と計測テスト、`ExperimentSceneBuilder`（実験シーンの生成元）が `SampleScene.unity` を決め打ちしており、**全て失敗する状態**だった

## 発表で強調するポイント

- **「Unity 側に情報がない」と思っていたものが、実は bundle に既にあった**。`manifest.json` の `shot_boundary_policy` は Unity 側の実装指針（`unity_guidance`）まで含めて書かれており、Python 側と Unity 側の分業がフォーマットの中で明文化されている好例
- カットは「モデルが動いた」のではなく「カメラが切り替わった」。同じ trackId でも見かけサイズが変わるのは正当な変化で、平滑化して追従させるべきではない。**平滑化してよい変化と、スナップすべき変化を区別する**のがこの修正の本質
- スケールをロックする設計自体は正しかった（外すと bbox のブレで伸縮する）。バグは「ロックしていたこと」ではなく「解除点が足りなかったこと」
- **実験フローで新しく作ったものは意外と少ない**。「置換なし」条件は既存の normal mode、「何周でも見られる」はループ再生設定、条件切り替えの封じ込めは既存ボタン 1 つの非生成。作り込んだのは提示順の割り付けとログで、再生系は既存機能の組み替えで足りた
- **対照条件の取り違えが最大の落とし穴**。bundle には除去前と除去後の 2 本の動画が入っており、置換なし条件に除去後（`video.mp4`）を使うと「人や動物が消えて穴が空いた映像」を見せることになる。テストでも「StereoOnly のときだけ normal mode になること」を明示的に固定した
- **「値が一致する」は搬送の証明であって規約の証明ではない**（深度符号の調査で双方が踏んだ落とし穴）。Unity 側は「bundle の `anchor_z` と sidecar の `median` が一致する」ことを、生成側は「bundle の値と `keypoints3d.json` が完全一致する」ことを根拠にしたが、どちらも反転漏れ・二重反転のどちらでも成立する。規約を確かめるには、その値が作られる**前段のデータ**（`depth.npz`）まで遡るしかなかった
- **符号の判定には「正解が既知のデータで手法を較正する」のが効いた**。同じ相関指標でも、符号が確定している `bundle_human.svb` で負が出ることを先に確認してから animal に適用したことで、「指標が壊れている」のか「符号が逆」なのかを切り分けられた。修正後に**絶対値を保ったまま符号だけ反転した**ことが、反転が 1 回だけ効いた確認にもなっている
- **無言で失敗する経路は作らない**。normal mode の黒画面は、動画がデコードできないという単純な事実にもかかわらず、`errorReceived` を購読していなかったために「UI もログも正常なのに画面だけ黒い」という切り分けにくい形で現れた。runtime が外部データを受け取る境界（動画・bundle・manifest）では、失敗を必ずログに出す
- **同じ bundle の中でも、用途が違うファイルは生成経路が違う**。`video.mp4` は libx264 で書かれていたのに `source/pre_removal_stereo_video.mp4` だけ mpeg4 だった。「片方が正しいから両方正しい」とは言えず、runtime が実際に使うファイルは個別に要件を満たしているか確認する必要がある
- **規約は manifest に書かせて runtime で分岐する**。`anchor_z` の向きが bundle 世代で変わったが、`depth_policy` の有無で判定する実装にしたので旧 bundle も再生できる。値から向きを推定する実装（深度が中央付近に固まると成立しない）やバージョン決め打ちは採らなかった

## 残課題

- **実機での確認が未実施**: 15 shot ある `bundle_animal.svb` でカット切り替え時の見た目を確認する必要がある。ログに `[Shot] boundary crossed. frame=... shotIndex=...` を出しているので、カットのタイミングと実際の切り替わりが一致しているかを合わせて確認する
- **interactive motion はリセット対象に含めていない**: カット中にインタラクティブモーションが再生されている場合の扱いは未定（継続すべきか中断すべきか）。仕様判断が必要
- **shots のレンジに隙間がある bundle** は、隙間のフレームを直前 shot の続きとして扱う（余計なリセットを避けるため）。現状の bundle はすべて隙間なしなので実害はない
- ~~**Human の姿勢再現度**: 座位・仰向けでモデルが縦に 1.5 倍はみ出す~~ → **解決**（`SpineBodyPoseScale` 0.25 → 1.0）。7 つの仮説を消去した先にあったのは FK 公式ではなく、**過去に入れた減衰係数**だった
- **接触補正の位置精度**: 飛びは止まったが Other が正しい位置に来ない。**ボール側の配置は完璧**（`sizeRatio` 1.000）と実測済み。姿勢とりまとめ（`SpineBodyPoseScale`）と深度符号の修正が入ったので、この状態で再評価が必要
- **接触補正の部位選択が固着する**: 2156 フレームで切替が 15 回しかなく、実際の接触部位に追従できていない場面がある
- **ボールが足に埋もれる場面が残る**: 人とボールの**配置深度差は平均 1.9 cm のまま**。符号は直ったが `PopoutRangeMeters = 0.35` に 0..1 を線形で押し込む構造は変えていない。`disp_min` / `disp_max` が manifest に載るようになったものの、DepthCrafter は affine-invariant（`disp_raw ≈ a/Z + b`、`a`,`b` は clip ごとに未知）なので、この 2 値だけでは絶対距離に較正できない
- **座って片足でリフティングし、もう片足がボールの周りを回る場面**の見た目が不自然（未着手）
- **深度変換式の反比例化**: disparity と確定したので理屈上は正しい修正。ただし全体 R² = 0.166 なので効果は限定的
- **`jointsWorld` のスケール未適用**（7/30 から継続）: `AlignHumanoidFeetYToSmplAnkles` が機能していない。打ち消しを解除してはいけない点に注意（[smpl-retargeting.md](../../smpl-retargeting.md)）
- **`Else: 8 prefab` 問題**: `Resources/Models/Else/Sources/DieselLocomotive.glb` が大文字始まりのため runtime のフィルタ（`IsPrefabNameStart`）を通過している。`Resources.LoadAll` の順序は保証されないため `trackModelIndices` の index ズレのリスクがある
- 7/31 からの継続課題（`updateWhenOffscreen = true` の副作用の実機確認、CC-BY-4.0 モデルのクレジット表示）
- **normal mode の実機再確認（生成側の修正待ち）**: pre_removal を H.264 で書き直した bundle で、Display の切り替えと実験の StereoOnly 条件（`startInNormalMode`）が実際に映ることを確認する。**「置換なし」条件はこの動画そのものなので、直るまで被験者実験は走らせられない**
- **Models パネルのレイ修正の実機確認**: prefab 経由に変えたことでパネルの位置・サイズ（980x660 → 0.84m x 0.58m）とプレビューモデルの表示が崩れていないかを合わせて見る
- **コントローラでの対象選択の実機確認**: 動画内の人／動物を指してトリガーを引き、`[Pick] track=...` が出ること、そのあと Models を開くと指した対象の候補が並ぶことを確認する。aim pose は OpenXR の `PointerPosition` が取れなければ `devicePosition`（握り位置）にフォールバックするので、ずれる場合はどちらが使われているかを疑う
- **モデル変更時のスケールの実機確認**: 同じ shot 内で再生位置を変えながら何度かモデルを変え、毎回同じ大きさになること。`bundle_animal.svb`（15 shot）でカットをまたいだ場合も従来どおり shot ごとに取り直されること
- **実験フローの実機確認が未実施**: シーン生成メニューの実行、6 試行の通し、ログの adb 回収までを一度通す必要がある。特に試行ごとの bundle 展開時間（`bundle_human.svb` は 155MB）が実験の進行として許容できるかを確認する
- **追加した Human 3 体の実機確認**: Models パネルのプレビュー表示、URP/Lit に作り直したマテリアルの見え方（特に肌の smoothness を 0.25 固定にした点と、法線マップの向き）を確認する。既存 14 体と質感が揃わない場合は `_Smoothness` の調整か `*_gm.tga` の利用を再検討する
- **FK 公式の左掛けへの修正**（未着手・上記調査の結論）: `tw[j] = Θ[j] * bindRotWorld[j]` に変えるとリグ非依存になる。`ApplyWorldRotation` のままで実現でき IK も不要、BONE MISSING の特殊分岐も消える。既存 14 体への影響は小さい見込み（胴・肩・腕の誤差 0〜6°、脚は AimAt が上書き）だが、**14 体すべての見た目を確認してから入れる**必要がある
- **Renderpeople の twist ボーン**（未着手）: 8 本が静止したままなのでひねり時にメッシュが破綻する。Avatar に登録できない以上、runtime で親の roll の半分を分配するか、リグ側で twist を除く判断が要る
- **07_Human_Beta（Mixamo）の肩**: bindRotWorld が 129° 乖離しており AimAt も掛からないため、現行公式では既にずれているはず。左掛け修正で一緒に直る想定だが、修正前後で比較して確認する
- **モデル変更を被験者に許可したことによる交絡**: 置換あり条件で見るモデルが参加者ごとに変わる。**モデルが 17 体に増えた**ぶん、参加者間のばらつきはさらに大きくなる。`operations.csv` に prefab 名まで記録して分析時に統制できるようにしたが、統制しきれないと判断した場合はモデルピッカーも非生成にする
- **試行の終了操作**: 現状は被験者自身が「視聴を終了」を押す方式（Quest 単体では実験者に入力手段がないため）。実験者側で制御したい場合は方式の変更が必要
