
# D-009: animal の `anchor_z` が bbox と食い違う（原因は depth ではなく AniMer の当てはめ）

← [課題一覧に戻る](README.md)

**状態**: **起票のみ・双方とも着手しない**（2026-09-09 に双方合意） ／ **提起**: [bundle側] 2026-09-09 ／ **対象**: `bundle_animal.svb`

> **この課題は寝かせている。** 実機で症状が観測されておらず、数字にも交絡がある。
> **後で animal に症状が出たときの出発点**として記録している。
> 着手するときは、まず下の「着手する前に確かめること」から。

### 経緯

[D-004](D-004-anchor-z-accuracy.md) で human の `anchor_z` の跳ねを追ったとき、
整合チェック（`anchor_bbox_consistency_check.py`）を 3 本の bundle にまとめてかけた。
その副産物として animal でも 11.0% の矛盾事象が出た。

当初は human と同じ「自己遮蔽」で説明できると考えたが、**機序が違うことが判明した**ので、
D-004 から切り出してここに記録する。

### 症状

`bundle_animal.svb` の track 0 で、**`bbox` がほとんど動いていないのに `anchor_z` が動く**
区間が 13 件、対象フレームの 11.0% を覆う（既定パラメータ、`rawAnchor.z`）。

| bundle | track | 矛盾事象 | 覆うフレーム | 隣接フレーム差 p99 |
|---|---|---|---|---|
| animal | 0 animal | 13 件 | 11.0% | 0.0485 |
| animal | 1 animal | 14 件 | 14.8% | 0.0221 |

大きい順に 3 件:

| 事象の区間 | 代表窓 | 秒 | Δbbox | 描画高 | アンカー移動 |
|---|---|---|---|---|---|
| 1028-1036 | 1029-1035 | 34.30-34.50 | −1.5% | 0.69 倍 | **108.6px** |
| 668-676 | 668-674 | 22.27-22.47 | −0.9% | 1.32 倍 | 13.5px |
| 136-158 | 150-156 | 5.00-5.20 | +0.2% | 1.18 倍 | **189.4px** |

### human とは機序が違う（ここが本題）

**animal の `anchor_z` は depth map を一度も読んでいない。**

| | |
|---|---|
| `rawAnchor.source` | `animal_camera_root` が track 0 で 1146/1146 件、track 1 で 974/974 件（**100%**） |
| `depthStats` | `validCount = 1`、`median` = `p10` = `p90` = `rawAnchor.z`。**合成された飾り** |
| 中身 | `build_bundle_svb.py` の `animal_camera_root_anchor()` が返す **AniMer のカメラ空間 root Z** |
| 単位 | `animer_joint_scale = 1.0` なので無変換。**AniMer 独自スケールでメートルではない**（実測レンジ 0.278〜0.748） |
| 平滑化 | **EMA を通っていない**（`anchor_source == "animal_camera_root"` の分岐で raw をそのまま採用。human は `ema_alpha=0.8`） |

したがって:

- **D-004 の human 向け対処（SAM2 マスク中央値化）は animal に一切効かない。**
  depth サンプリングをしていないので、その改善が届かない
- 上位 2 件でアンカーが 108.6px / 189.4px 飛んでいることから、
  **AniMer の当てはめが不安定なフレームで root がジャンプしている**、という筋が濃い

### 数字の交絡（ここが「寝かせる」根拠の一つ）

animal track 0 は **`bbox` が画面端に接するフレームが 63.9%**（矛盾事象の中では 74.1%）。
`bbox` が切れていると「見かけの大きさが変わっていない」という検出の前提そのものが弱い。

`anchor_bbox_consistency_check.py --skip-edge-touch` で端に接するフレームを除くと
**3 件 / 5.1%** になるが、**1146 → 414 フレームしか残らないので 11.0% と並べて比較できない。**
参考値としてのみ。

### 着手しない理由（2026-09-09、双方合意）

[Unity側] が挙げた 3 点:

1. **animal の症状は実機で観測されていない。** 実機で報告されたのは human の
   26.7 秒（0.81 倍）と 35.9 秒（1.29 倍）の 2 件だけで、animal を通しで確認した事実がない
2. **11.0% という数字自体に交絡がある**（上記の画面端 63.9%）
3. **この数字は 3 本の bundle に一括でツールをかけて出したもので、症状の報告に基づいていない。**
   優先度を上げる材料がない

### 着手する前に確かめること

1. **実機で animal を通しで見て、症状が知覚できるか。** 上の 3 件（5.0s / 22.3s / 34.4s）が
   出発点。ここで何も見えないなら、この課題は閉じてよい
2. **`--skip-edge-touch` で残る 3 件が実機の症状と対応するか。**
   画面端の交絡を除いてなお残るものが本体のはず
3. **AniMer の root ジャンプが元データの時点で起きているか。**
   `Human/animal_demo_work_1280x720_keypoints3d.json` の `pose.keypoints3d` を直接見る。
   bundle 側の変換ではなく AniMer 出力の問題なら、対処は AniMer 側になる
