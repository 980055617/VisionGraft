### 症状

Unity 側は `meta.bin` の `anchor_z`（正規化 disparity）を `Z ∝ 1/disparity` と解釈して、オブジェクトを画面手前の popout レンジに配置している。この解釈で得た距離が、**幾何的に求めた実距離と系統的にずれる**。

結果として、同一フレーム内の 2 オブジェクト（人とボール）の前後関係とサイズ比が崩れ、モデルがボールを飲み込む・逆に浮きすぎる、という症状が出る。単一のスケール係数では両立できないことを実測で確認済み。

### 測定方法

**実距離の求め方（depth map を一切使わない）**

- `person` / `animal`: `meta.bin` の keypoints3d（root 相対・カメラ空間・実寸メートル、実寸であることは別途検証済み）を距離 Z で透視投影し、**その投影高が bbox 高と一致する Z** を二分探索で求める。カメラ内部パラメータは `manifest.json` の `fy_norm` / `eye_h` を使用
- `other`: keypoints がないため実サイズ不明。bbox 径の逆数を相対距離とした（**この推定は物体の回転・変形に弱い**ので、下表の `other` 側は上限値として読んでほしい）

**フィット**

`disparity = a/Z + b` を最小二乗でフィットし、決定係数を見た（DepthCrafter は affine-invariant なので、この形が成り立つのが前提）。

### Unity 側で確認済みのこと（＝そちらに対応をお願いする理由）

- **`a`, `b` の較正では直せない。** Unity は最終的に disparity を popout レンジへ線形正規化して押し込むので、`Z = a/(disp − b)` の `a`（スケール）と `b`（シフト）は**正規化に吸収されて完全に消える**。実際に全編較正・3 秒ごとの区間別較正の両方を試算したが、`boneRatio` のばらつきは 1.22 倍のまま変わらなかった
- **実距離を直接使えば改善するが、汎用性がない。** keypoints 由来の実距離をそのまま使うと ばらつき 1.22 → 1.12 倍、問題区間の過大投影 1.391 → 1.166 に改善する。ただしこれは keypoints を持つ `person` / `animal` にしか使えず、**`bundle_train.svb` のように `other` のみで構成される bundle には原理的に適用できない**。また人だけ基準を変えると人と `other` で深度の基準がずれ、前後関係が壊れる
- D-001（クリップ全体の時間ドリフト）は修正済みで、これはその修正後のビルドでの測定。**別軸の問題**

#### 訂正: ラグ1自己相関の数値がEMAで水増しされていた

`source/placement_observations.json` の `rawAnchor.z`（EMA適用前の生サンプル、held frameにも入っている）で計算し直した。
