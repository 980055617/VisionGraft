# D-001: 1 shot の長尺クリップで `anchor_z` がドリフトする

← [課題一覧に戻る](README.md)

**状態**: **解決**（2026-09-04）　**提起**: [Unity側] 2026-08-17

### 報告 `[Unity側]`

#### 要約

`bundle_human.svb` / `bundle_train.svb` で **`meta.bin` の `anchor_z` が被写体の距離を表していない**。
同じパイプラインで生成された `bundle_animal.svb` は正常なので、**原理的な限界ではなく特定条件で起きる不具合**。

条件は **shot 数**と対応している。

| bundle | shots | 長さ | 判定 | 判定に使った指標 |
|---|---|---|---|---|
| `bundle_animal.svb` | **15** | 71 s | **OK** | corr(SMAL `transl.z`, `z01`) = **+0.550 / +0.624** |
| `bundle_human.svb` | **1** | 72 s | **NG** | corr(SMPL `transl.z`, `z01`) = **+0.026** |
| `bundle_train.svb` | **1** | 61 s | **NG** | corr(bbox 径, `z01`) が全 8 track で**正**（負であるべき） |

2026-08-05 に対処された「チャンク間ドリフト」（全体 R² 0.0037 → 0.1657）の**残存**と考えている。R² 0.1657 は相関で言えば 0.41 でまだ足りない。カットが多い素材では shot 境界がドリフトの蓄積を実質的に断ち切るため露見せず、**1 shot の長尺クリップでのみ症状が出る**、という説明がすべての観測と整合する。

#### 利用側で起きること

`anchor_z` は popout レンジ（0.35 m）に写されてオブジェクトの配置深度になる。`bundle_human.svb` の実測:

- 立位（keypoint 身長 1.45–1.75 m）かつ `transl.z` がほぼ同じ = **人が同じ場所に立っている 386 フレーム**で、`z01` が **0.180〜0.398** に散る
- 配置深度に直すと **253 mm のばらつき**。表示身長 0.398 m の **64%**
- 人とボールの深度差は median 80 mm なので、**ばらつきが深度差の 3.8 倍**
- 人とボールの前後関係の一致率は **33%**（偶然の 50% より悪い）

見た目の症状は「胸トラップや足でボールを扱う場面で、ボールが人体に埋もれる」。

#### 根拠

**1. 距離を正しく捉えている系列が 2 つあり、互いに一致している**

`bundle_human.svb` の person track（1 秒 median に平滑化）で corr(SMPL `transl.z`, 1/`bboxH`) = **+0.691**。
`transl.z`（4D-Human の weak-perspective カメラ距離）と `bboxH`（検出 bbox 高さ）は**独立した推定**なので、一致していることは両方が距離を捉えている証拠。

**2. `anchor_z` だけが無相関**

| 検証 | 値 | あるべき値 |
|---|---|---|
| corr(`transl.z`, `z01`) | **+0.026** | +1 に近い |
| ↑ 立位フレームのみ | +0.078 | +1 に近い |
| corr(1/`bboxH`, `z01`) | −0.109 | +1 に近い |

**3. 同じ bundle のボールは正常**

corr(ボール bbox 径, ボールの `z01`) = **−0.456** ✓（実サイズ一定なので径 ∝ 1/距離、負相関が正しい）。
**同じ depth map から取っているのに person track だけが壊れている。**

**4. 狂い方は単調ドリフト**

| 検証 | 値 |
|---|---|
| corr(person `z01`, **経過時間**) | **+0.657** |
| corr(ball `z01`, 経過時間) | +0.415 |
| corr(person `z01`, ball `z01`) | **+0.679** |

1 秒 median の推移:

| 時刻 | `transl.z` | `bboxH` | `z01` |
|---|---|---|---|
| 0 s | 102.2 | 414 | **0.195** |
| 24 s | 129.5 | 198 | 0.365 |
| 48 s | 100.4 | 441 | **0.310** |
| 72 s | 79.8 | 305 | 0.282 |

**0 秒と 48 秒は `transl.z`（102.2 / 100.4）も `bboxH`（414 / 441）もほぼ同じ = 同じ距離に同じ姿勢で立っている。それなのに `z01` は 0.195 と 0.310。**

`bundle_train.svb` の track 0 はさらに露骨で、`z01` が 0.506 → 0.952 へ単調増加（corr(`z01`, 経過時間) = **+0.951**）。

**5. ドリフトはシーン内の全オブジェクトに共通**

corr(person `z01`, ball `z01`) = +0.679。人とボールが**一緒に流れている**。差分を取ると前後関係がかなり回復する。

| 前後関係の一致率 | |
|---|---|
| 生の `z01` | **33%** |
| 人の `z01` − ボールの `z01` | **74%** |

**同一フレーム内の相対順序としては情報が残っており、失われているのは絶対値のほう。** ドリフトが「フレームごとの共通オフセット」として乗っていることを裏づける。

#### 生成側の観測ログは正常と報告している

`source/placement_observations.json` の person track:

| 項目 | 値 |
|---|---|
| `placementConfidence` | median **1.0**、低信頼 0.0% |
| `placementStatus` | 全 2167 フレーム `high` |
| `placementHeld` | **0.0%** |
| anchor source | 全て `depth_sample` |
| bbox 内 depth の IQR | median 0.00195（有効サンプル 49） |

**観測ゲート・hold・信頼度のいずれも異常を検出していない。** anchor のサンプリングは想定どおり動いており、サンプリング元の depth 値そのものが時間方向に流れている、という切り分けになる。

#### 確認したいこと

1. `--depth-chunk-size` / overlap のチェーン式アフィン合わせは 2026-08-05 に見直されたが、**1 shot 60〜70 秒（1800〜2200 フレーム）の素材で蓄積誤差が残っていないか**
2. `bundle_animal.svb`（15 shot）が正常なのは、**shot 境界でアフィン合わせが実質リセットされているから**という理解で合っているか。もしそうなら、カットのない素材には別の基準点が要る
3. チャンク間のアフィン合わせを**チェーンではなく共通参照**に変えられないか。クリップ全体で 1 回 min-max 正規化する現在の方針（`global_minmax_pre_clip`）とは別に、チャンク間がチェーンになっている点が蓄積の原因に見える

#### 修正後の判定基準

優先順位のとおりに確認してほしい。

| 優先 | 指標 | 目標 | 対象 |
|---|---|---|---|
| 1 | corr(`transl.z`, `z01`) | **> 0.5** | SMPL/SMAL を持つ track |
| 2 | corr(bbox 径, `z01`) | **< −0.3** | 実サイズ一定の Else track |
| 3 | corr(`z01`, 経過時間) | 0 に近い | 参考値 |

**指標 3 は単独では判定に使えない。** 被写体が一方向へ動き続ける映像（電車が遠ざかる等）では大きくて当然なので、指標 1 や 2 が NG のときに「狂い方が単調ドリフトなのか」を見分けるために使う。

指標 1 を使う前に **corr(`transl.z`, 1/`bboxH`) > 0.5** を確認すること。ここが低い場合は `transl.z` 自体が信用できない（フレーム数不足・推定が不安定）ので基準にできない。旧 `bundle.svb`（289 フレーム = 10 秒）が該当する。

#### 再現手順

```
python bundle_depth_check.py path/to/bundle.svb [more.svb ...]
```

`anchor_z` の抽出品質を見るときは:

```
python anchor_quality_check.py path/to/bundle.svb
```

**このフォルダ内の `bundle_depth_check.py`**。標準ライブラリのみで動く単一ファイルなので、どちらの環境でもそのまま走る。`.svb` の `meta.bin` + `manifest.json` だけを読み、track ごとに上の 3 指標と 1 秒 median の推移を出す。判定の符号は bundle 世代（`depth_policy` の有無 = `larger = farther` / `nearer`）を吸収済み。

**このツールは必須ではない**（生成側は `meta.bin` を作っている当事者なので読むコードは持っているはず）。同梱している理由は、判定基準を文章で書くだけでは解釈がぶれるため。1 秒 median に平滑化するかどうか、立位で絞るかどうか、旧世代の符号をどちら向きに正規化するかで値が変わり（`bundle_human.svb` の指標 1 は絞り方で +0.026 / +0.078 と動く）、「こちらでは 0.5 を超えた」という食い違いが起きる。**自前で書き直しても構わないが、その場合は同じ数字が出ることを確認してほしい。**

なお**原因究明には向かない**。生成側は `depth.npz` の生値・チャンク境界・アフィン係数の履歴を見られるので、そちらのほうが直接的。これは `.svb` の出力だけを見る**最終成果物の検査ツール**。

### 回答 `[bundle側]`

#### 結論

**原因は特定できた。ただし「2026-08-05 のチャンク間ドリフト修正が不十分」ではない。修正自体は効いている。渡っていた `bundle_human.svb` / `bundle_train.svb` が、その修正より前に作った `depth.npz` のままビルドされていた、というだけ。** `bundle_depth_check.py` を使って手元で再現・検証済み。

`shared_volume/sam2_bundle_jobs/` を見ると、2026-08-05 にチャンク間アフィン合わせを「チェーン」から「全ペアの重なりを同時に解く joint least-squares」に変更する修正（`StereoCrafter/depth_splatting_inference.py` の `_solve_global_chunk_affine`、report 内の確認したいこと #3 そのもの）が入っており、`20260805-{human,train,animal}-depth-chunkfix/` という検証専用ジョブで `depth.npz` を再生成して `bundle.svb` を作り直し、効果を確認していた形跡がある。**しかしこの再生成された `depth.npz` は `FINNAL_HUMAN` / `FINNAL_TRAIN` の本番ディレクトリには一度もコピーされておらず、そこにある `depth.npz` は今も 2026-07-27（human）/ 2026-07-29（train）時点の、修正前のものだった。**

紛らわしい点として、`bundle_shots_depthfix.svb`（2026-08-06 生成）や `bundle_shots_h264fix.svb`（2026-08-07 生成）はファイル名だけ見ると「直っていそう」だが、中身の `depth.npz` は差し替わっていない。この2つの "fix" はどちらも別件（`depthfix` = anchor_z の符号規約統一、`h264fix` = Quest 向け H264 再エンコード）で、チャンクドリフト修正とは無関係。命名が衝突していて紛らわしかった。

#### 検証

`20260805-*-depth-chunkfix/` に残っていた再生成済み `depth.npz` を使い、現行の `build_bundle_svb.py`（2026-08-06 の anchor_z 規約修正込み）でビルドし直し、渡された `bundle_depth_check.py` で確認した。

| human track0 | corr(z01, 経過時間) | ±0.68（単調） | -0.12 |
| train track0 | corr(z01, 経過時間) | **+0.951**（report記載の 0.506→0.952 そのもの） | **+0.33**、推移はほぼ平坦（0.79〜0.83） |

train は他の短尺 "other" track（8〜33秒しかない車両ごとの track）で corr(bbox径, z01) が一部まだ NG のままだが、この指標はツール自身のコメント通り「画面外への切れ・隠れに弱い参考値」で、かつ**全 track が揃って +0.9〜0.96 という「同じ方向に流れる」シグネチャ（report の根拠5と同じパターン）が、修正後は track ごとにバラバラで弱い値になった**。これは共通のドリフトではなく個々のオブジェクトの実際の動きと見るのが妥当。

#### 確認したいこと（report内の3項目）への回答

1. **残っていたか** → 残っていたが、原因は「合わせ方が甘い」ではなく「修正後の `depth.npz` が本番ディレクトリに配布されていなかった」。修正後の `depth.npz` を使えば 1800〜2200 フレームの単一 shot でも上の指標は通る。

### 追加報告 `[Unity側]` 2026-08-17

原因の特定と検証、ありがとうございます。3 点あります。

#### 1. animal の `depth_policy` は宣言どおりで問題ない（副次的発見への回答）

**Unity 側が実際に配布を受けている `bundle_animal.svb`（`generated_at: 2026-08-06T06:33:19Z`、`depth_policy` あり）で、両方の向きを仮定して相関を取り直した。**

| track | corr(SMAL `transl.z`, `z01`) 生の値 | `larger = farther` と仮定 | `larger = nearer` と仮定 |
|---|---|---|---|
| track 0 (animal) | +0.550 | **+0.550 → OK** | −0.550 → NG |
| track 1 (animal) | +0.624 | **+0.624 → OK** | −0.624 → NG |

**`larger = farther` でなければ成立しない。** 基準にした `transl.z` 自体の妥当性も corr(`transl.z`, 1/`bboxH`) = +0.956 / +0.690 で確認済み。

「`bundle_shots.svb` と `anchor_z` がビット単位で同一」なのは、**そちらの回答にある `animal_camera_root` 経路が前から独立して符号反転済みだったことの当然の帰結**と考えている。animal は旧版の時点ですでに `larger = farther` だったので、`depth_policy` を宣言してもデータを変える必要がなかった。逆に person / other は旧版が `larger = nearer` だったので depthfix で反転してデータが変わった。**animal だけビット同一なのは期待どおりの挙動**で、宣言の誤りではない。

したがって `bundle_depth_check.py` の「manifest に `depth_policy` があれば全 track farther」という前提も、少なくとも現行 animal では成立している。**animal の `*_depthfix.svb` は使用を避けなくてよいと考えるが、そちらの調査で別の材料が出たら教えてほしい。**

#### 2. 「shot 数と対応している」という当方の説明は撤回する

report の要約に書いた「カットが多い素材では shot 境界がドリフトの蓄積を実質的に断ち切るため露見せず、1 shot の長尺クリップでのみ症状が出る」は**誤り**。そちらの実装確認（`shots.json` は inpaint 段と bundle 構築段にしか渡っておらず、`depth_splatting_inference.py` に shots の概念がない）のとおり。

**3 bundle という少ないサンプルで観測された相関を、機構を確認せずに因果として書いてしまった。** 判断材料を誤らせて申し訳ない。

#### 3. `FINNAL_ANIMAL` の `depth.npz` の日付を確認してほしい

そちらの回答では、animal が元々 OK だった理由を「たまたま animal の該当区間の残差が小さかった／ノイズの範囲」としている。ただし**回答中で「本番ディレクトリにコピーされていない」と明記されているのは `FINNAL_HUMAN` / `FINNAL_TRAIN` の 2 つで、`FINNAL_ANIMAL` については言及がない**。

`20260805-animal-depth-chunkfix/` も作られている以上、**animal だけは修正後の `depth.npz` が本番に反映されていた**という可能性がある。もしそうなら「animal だけ OK だった」ことが偶然ではなく完全に説明でき、今回の切り分けの確度も上がる。`FINNAL_ANIMAL/*_depth.npz` のタイムスタンプが 2026-08-05 以降かどうかを見てもらえないか。

#### 4. 訂正: 報告の「前後関係の一致率 33%」は当方の計算誤り

report の「利用側で起きること」と「根拠 5」に書いた **「人とボールの前後関係の一致率は 33%（偶然の 50% より悪い）」「差分を取ると 74% に回復」は誤り**なので取り消す。

この計算は「映像上の bbox 径とボールの実サイズから真の距離比を逆算する」方式だが、**実サイズをサッカーボールの 0.22 m と仮定していた。この素材はハンドボール**（男子 3 号 = 直径 0.185〜0.19 m）である。

| ボール実サイズの仮定 | 真の `z_ball/z_human` median | 一致率 |
|---|---|---|
| 0.185 m（ハンドボール男子3号） | 0.902 | **77.6%** |
| 0.19 m | 0.926 | **75.6%** |
| 0.22 m（サッカーボール）← 誤って使っていた | 1.072 | 32.4% |
| 0.25 m | 1.218 | 15.9% |

**3 cm の仮定違いで 32% → 76% に振れる。この指標は実サイズ仮定に敏感すぎて判定に使えない。** D-001 の判定基準（優先 1〜3）には含めていないので判定自体への影響はないが、根拠として提示した数値なので訂正する。
