# Interactive Motion Events

Interactive motion events are optional behaviors inserted during stereo video playback to make displayed person and animal tracks feel more responsive. They are enabled by default and can be disabled at runtime from the settings panel with the `Motion` toggle.

## Runtime Behavior

- Events are scheduled per displayed track at random intervals.
- Replacement events sync to the tracked model at the start and blend back toward tracking at the end.
- Overlay events keep the tracked root placement and add a local gesture on top of the current pose.
- Frame-out handling keeps a selected track active briefly when tracking data disappears and runs a replacement-style motion from the last known tracked transform.
- In-frame Human events are mostly in-place gestures. Approach motion is intentionally occasional so the subject does not walk toward the viewer every time.
- Replacement motion preserves the tracked vertical height while blending, so returning to tracking should not cause a visible height pop.
- Human clips blend their bone rotations in and out instead of snapping directly to the authored clip.
- Human events rebuild the root rotation as an upright yaw rotation and bias it toward the viewer, so a crouched tracked pose should not make the inserted animation lean diagonally.
- Human gesture clips play once by default. Clips whose names contain `walk`, `run`, `step`, or `approach` are treated as walking-style clips and may loop during approach events.

## Human Tracks

Human tracks use replacement events first because Unity Humanoid animation clips are the easiest animation assets to source and retarget.

Configure clips from the `StreamingStereoVideoPlayer` inspector:

- `Human Interactive Clips`: Humanoid-compatible `AnimationClip` assets generated by AI tools, Mixamo, mocap, or hand-authored in Unity.
- `Interactive Motion Duration Seconds`: event length.
- `Interactive Motion Blend Seconds`: blend-in and blend-out time.
- `Interactive Approach Distance Meters`: procedural root offset used while the event is active.

At runtime, the player uses Playables to sample the selected clip on the track's child `Animator`. If no clip is assigned, the system falls back to a simple right-arm wave so the feature can still be tested.

The implementation enforces a minimum motion duration and blend time even if older scene data contains faster values. This keeps approach events human-paced rather than snapping forward and back. In-place clips keep the tracked root position and only blend the humanoid pose.

## Animal Tracks

Animal tracks use built-in motion presets instead of imported clips. This avoids depending on a universal animal retargeting setup, which Unity does not provide for arbitrary quadrupeds.

Current presets:

- `LookAtViewer`: steers the head target toward the viewer.
- `TailWag`: offsets the tail tip side-to-side when animal control targets are available.
- `PawWave`: raises and waves the front-right paw target.
- `ApproachViewer`: replacement-style root motion toward the viewer, blended back to tracking.

Animal presets are applied before `AnimalPoseApplier` consumes the pose, so the existing root placement, head, tail, and limb solving remain the final authority.

## Implementation Map

- `StreamingStereoVideoPlayer.InteractiveMotion.partial.cs`: scheduler, event state, Human Playables playback, Animal preset pose edits, frame-out handling.
- `StreamingStereoVideoPlayer.Playback.partial.cs`: observes visible tracks, starts events, preserves selected frame-out tracks, and skips bbox fitting during replacement events.
- `StreamingStereoVideoPlayer.PosePipeline.partial.cs`: applies Human replacement events before IK, Human overlay clips after IK, and Animal pose preset edits.
- `StreamingStereoVideoPlayer.UI.*`: adds the runtime `Motion` ON/OFF toggle.

## Asset Guidance

For Human clips, prefer Humanoid-compatible assets. AI-generated or downloaded FBX animations should be imported as Humanoid and checked against the model avatar before assigning them.

For Animal animation, start with presets or model-specific clips. Generic AI-generated animal FBX clips usually require matching bone names, hierarchy, orientation, and scale before they can be applied reliably.
