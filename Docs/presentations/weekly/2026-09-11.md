## 1. Screen Dist を動かすと Human の配置が壊れる — 解決

### 症状

設定の Screen Dist を動かしても距離が変わって見えず、スクリーンも Else もその場にあるのに
Human だけが挙動を変える。

### 原因: ⑧ が root を「モデルの深度」として扱っていた

`instance.transform.position`（root）は体（Hips）から手前にずれている。
ずれ幅は **1.0m で 0.22m、3.0m で 2.45m**（×11）。

⑧ `RefineDepthFromProjectedBones` の順序クランプ `ClampRatioPreservingOtherOrder` が
その root の深度（3.0m 設定で 0.408m）を Else の配置深度（2.72m）と比べ、
「人がボールより手前すぎる」と誤判定して倍率を **6.403** まで押し上げていた。

**生の比のガード上限は 3.0 なので、6.403 は投影からは出ない値。**これが決め手だった。
押し出された結果、体は 2.86m → 5.30m（スクリーンより奥）へ飛び、
`boneRatio` が 0.54 まで落ちていた（`2.86 / 5.30 = 0.540` と一致）。

### 対処

⑧ の深度を **root ではなく体（Humanoid の Hips）で解く**。

- 順序クランプにも体の深度を渡す
- `screenDist` のクランプも体に掛ける（root に掛けると root だけ止まり体は奥に残る）
- 位置ベクトルを倍率で伸ばす形をやめ、**体の移動量ぶんだけ root を平行移動**する

### 結果

| screenDist | shot 先頭 boneRatio（修正前 → 後）|
|---|---|
| 1.0m | 0.869 → **1.009** |
| 2.0m（既定）| — → **1.019** |
| 3.0m | **0.536 → 1.050** |

距離で 1.6 倍違っていたのが揃った。Animal は Generic リグで従来経路のまま（退行なし）。

### 残課題

`[DEPTH9]`（Else を人の骨格基準で置く段）が基準にする人の深度は、修正後も
1.000 / 3.000 と **screenDist のクランプに張り付いたまま**。ボールの移動量は
188mm → 92mm に減ったが、結合自体は直っていない。

## 2. 毛・ヒゲのカードが正しく描かれていない — 解決（17 件）

### 症状 2 種

- **ライオンのたてがみが透ける** — Transparent + alpha clip 無し
- **Hare のヒゲが白い板** — Opaque + alpha clip 無し（alpha が完全に無視される）

どちらも本体は「alpha clip が立っていない」。**判定は Surface ではなく `_AlphaClip` で見る。**

### 対処

`Assets/Editor/FurCardMaterialPostprocessor.cs`。マテリアルが FBX 埋め込みで `.mat` が
無いため、取り込み時（`OnPostprocessModel`）に cutout へ倒す。

**名前だけでは「毛のカード」と「毛のシェル」を区別できない**ので、
テクスチャの alpha を実測して完全透明の画素が 5% を超えるものだけを対象にした。

| | 最初 | 最終 |
|---|---:|---:|
| Transparent なマテリアル | 6 | **0** |
| `alphaClip=1` のマテリアル | 35 | **50** |

### つまずいた点 3 つ（記録）

1. `OnPostprocessMaterial` は `materialImportMode: 2` では呼ばれない → `OnPostprocessModel` を使う
2. palette(P) 形式でも tRNS で透明を持てる。`convert("RGBA")` してから数える
3. `Texture2D.LoadImage` は PNG/JPG のみ。`.tga` 用に簡易デコーダを書いた

プロジェクト全体の `t:Material` を走査して無関係な 12 件に差分を出す事故もあった
（`LoadAssetAtPath` だけで Unity がプロパティ同期を走らせる）。

## 3. モデルを変えると後ろ足の曲がりが変わる — コードでは直せないと結論

### 原因: 実行時の姿勢は bind pose でほぼ決まる

`meta.bin` の SMAL `body_pose` は「SMAL の rest から何度曲げるか」の**差分**なので、
**結果 = そのモデルの bind + 差分**になる。

実行時の膝角と bind の膝角の相関は **r² = 0.955、傾き 0.84**。
同じフレームでのモデル間の幅は **中央 103°・最大 126°**。
bind で脚が折れているモデル（49_Rabbit 156° / 33_Hare 149° / 06_AmericanMink 136°）は
何を再生しても後ろ足が折り畳まれたままになる。

### 3 方式を試して全て却下

| 方式 | 数値 | 絵 |
|---|---|---|
| 絶対姿勢（jointFrameMap 差し替え）| 膝の幅 103°→**0°** | 四肢が破綻 |
| bind を基準（27_GermanShepherd）へ揃える | 膝角 59〜60° に一致 | メッシュがねじれる |
| bind の開き角に上限 60° | 犬は無変更 | 触ったモデルが変形 |

**共通の原因はスキニング。**スキンはそのモデル自身の bind pose に対して張られているので、
ボーンを bind から大きく回すとメッシュが変形する。基準へ揃えるのに必要な回転量は
実測で 34〜140°（49_Rabbit は 100°・106°）。
**直したいモデルほど大きく回す必要があり、直せない。**

進めるなら asset 側（各リグの bind pose を作り直してスキンを張り直す）になる。

### 副産物

- **見かけの大きさは揃っていた** — 8 モデルで sizeRatio 0.986〜1.410、犬 4 種なら ±6%。
  ⑨ が shot 先頭で骨の投影スパンを bbox に合わせ込むため
- **`30_Goose` / `32_Guineafowl` / `35_Kangaroo` / `46_Pheasant` は正規の脚ボーンを持たない**
  （5 番目の指摘「アヒル・カンガルー」の答え）
- `Assets/Resources/Models/Animal/Sources/` に index 外の生 fbx が 10 個ある（ビルドに焼かれる）

## 4. 実機の VR 操作まわり（9/7 追加分）

実機で触ってもらって出た指摘を 4 件。**3 件解決、1 件は原因まで。**

### 画面が設定パネルに被って戻れない — 解決

頭が 0.35m / 35° 動くと画面が新しい正面へ飛ぶ実装だった。設定を触るために
視線を動かすとそれが発動していた。**頭の動きによる再センタリングを廃止**し、
画面はトラッキング原点（Reset View で決まる正面）に固定した。

### UI が使いにくい — 解決

- **小さい** → 視点から 1.2m に固定して視点へ正対させた
- **Screen Dist を動かすと上下する** → 原因は「画面の端からの隙間」が固定値だったこと。
  画面は距離に比例して大きくなるので角度としては一定だが、隙間だけが取り残されて
  UI が画面に寄っていた。**隙間の側を距離に比例させる**のが正しい向き
  （最初は画面サイズを換算して**逆に動かした**）

### Screen Dist を動かすと画面が左右に付いてくる — 解決

スライダーは値が変わるたび画面を置き直すが、その基準点が
**「そのときの頭の位置」**だった。向きだけ原点から取り、位置は頭のままだったので、
首を振ってからスライダーを触ると画面もモデルも頭へスナップし直していた。

**基準点を最初の目の位置で固定**した。バッチに `-headShift` を足して測ると:

| | スクリーンの中心 x |
|---|---:|
| 基準（視点を動かさない）| 959.5 px |
| 修正前 | **959.5 px（±0.0）** |
| 修正後 | **864.5 px（−95.0）** |

**修正前は視点を 0.35m 動かしても画面が 1 画素も動かない** = 完全に付いてきていた。

代償として、基準点から頭を大きく動かすと立体感が歪む（左右の目の間隔は
基準点から見て正しくしてあるため）。要求とのトレードオフ。

### コントローラのレイが 2 本・始点がずれる — 原因の半分まで

- 自前のレイは 1 本しか作っていない（`LineRenderer` はプロジェクトに 1 箇所）
- リグの二重化でもない（`Additive` で重ねる `TrialScene` は ISDK リグを持たない）
- **自前のレイは aim pose を正しく使えている**（実機ログ `[RAY] …=aim`）
- ISDK リグは `ControllerRayInteractor` と `HandRayInteractor` の**両方**を積んでいて、
  コントローラを握った手を合成するモード（`SyntheticHandData`）で動いている

**ISDK 側だけで 2 本出ている可能性が高い**が、切り分けは実機の目視待ち。

### NG として記録したこと

- **基準点を床のトラッキング原点にしない。**目より 1.6m 下から投影することになり、
  実機で「human の体勢が変わった」と言われた。原点から取ってよいのは**向きだけ**
- **UI の位置を直すのに画面のサイズを換算しない。**動くのは隙間の側

## 5. 頭の向きが合わない（指摘 4）— 解決

### 症状

27〜30 秒、元動画の犬は**真正面（カメラ）を見ている**のに、モデルは**左向きの横顔**のまま。
「原因を特定して直せるまで勝手に解決した気になるな」と指摘を受けた箇所。

### まずデータを疑って、潰した

`keypoints3d` と `body_pose` をカメラ空間で突き合わせた。

| 区間 | kp 鼻と smal 口の差 | 頭の振り kp | 頭の振り smal | 鼻の z（kp）|
|---|---:|---:|---:|---:|
| 全編 | 21.9° | 24.3° | 48.8° | -0.84 |
| **27〜30 秒** | 21.7° | **68.5°** | **68.0°** | **-0.97** |

z 負はカメラ側。**鼻の z = -0.97 は「ほぼ真っ直ぐこちらを向いている」**で元動画どおり。
体軸と鼻のなす角（頭の振り）も 2 つのデータ源で 68° 一致。
**データは頭の振りを持っていた。落としていたのはこちら側。**

### 原因は 2 つの「式の食い違い」

頭だけ Unity のリグに口・鼻のボーンが無く、照準が頭メッシュの重心になっていた。
そこでモデルごとに**照準（2 自由度）とロール θ（1 自由度）をクリップ全体から当てはめた**が、
**当てはめた式と実行する式が 2 か所で違っていた。**

1. 当てはめは `M = FromToRotation` 前提、runtime は耳ベースの 2 軸基底 → 二重補正
2. 当てはめは運動連鎖 `Aacc` 前提、runtime は頭だけ連鎖から外して**ローカル回転のみ**

2 は致命的で、頭の振り 68° は首・背骨に乗っているのでローカル回転には届かない。

### 結果

`[HEADAIM]`（適用後の頭ボーンの照準）と keypoints3d の 頭→鼻 の角度差:

| | 修正前 | 当てはめのみ | **両方の式を揃えた** |
|---|---:|---:|---:|
| 00_Dog 全編 | 45.4° | 26.0° | **18.9°** |
| **00_Dog 27〜30 秒** | 95.9° | 44.3° | **11.3°** |
| 36_LabradorDog 全編 | 106.9° | 27.4° | **19.1°** |
| **36_LabradorDog 27〜30 秒** | 90.6° | 45.1° | **6.5°** |

四肢（`[ANIMALKP]` の Paw 除外平均）は 23.0→23.1° / 42.7→42.8° で**変化なし**。

絵は `Docs/tmp/animal_head_chain.png`（頭の拡大）と
`animal_head_chain_3panel_dog.png` / `_lab.png`（元動画 / キーポイント / モデル）。

### 進め方として効いたこと

- **Unity を回す前にオフラインで予測した。**`[HEADFIT]` に `restWorldRot` を出しておくと、
  当てはめも「連鎖を入れたらどうなるか」もログだけで計算できる。
  予測 11.9° / 7.9° に対し実測 11.3° / 6.5°
- **予測模型自体を検算した。**現行構成（連鎖なし）で予測 43.9° / 42.1° を出させ、
  実測 44.3° / 45.1° を再現することを確認してから、変更後の予測を信用した
- **分岐が本当に切り替わったかをログに出した**（`useChain=`）。
  「直したのに効かない」と「そもそも通っていない」を取り違えないため

### NG として記録したこと

- **当てはめで決めたパラメータは、当てはめに使った式と同じ式で使う。**
  今回は 2 回同じ種類の食い違いを踏んだ
- **同名フィールドが 2 か所にある場合、既定値は上流で変える。**
  `excludeHeadFromChain` / `headAimFromModelForward` は
  `StreamingStereoVideoPlayer` が毎フレーム applier へ代入するので、applier 側だけ変えても効かない
- **可視化の切り出しを割合で決めない。**「外接矩形の左 45%」で切ったら、
  前肢が頭より前に出るフレームで頭が枠外になり草だけのコマを見せてしまった

### 残る課題

27〜30 秒はモデルが立ち姿、実写は伏せ。これは頭とは別で、この区間の `body_pose` 自体が
屈曲不足（後膝 111/136° に対し座位 122/123°・rest 147°）。生成側に出す。
