  - **bundle 側のデータは正しかった**: `meta.bin` の正規化深度 `z01` は 83.6% のフレームで「ボールが Human より手前」を正しく記録していた
  - **原因は Unity 側**: Else カテゴリだけ `ApplyMetaTarget` が `meta.bin` の anchor を捨てて `source/other_object_proxies.json` の値で上書きしていた。この sidecar の `cameraXyz` は `units="same_as_depth_npz"`、つまり 0=far/1=near の正規化深度でメートルではないため、そのまま world 座標に流すと前後関係が反転する。全 2156 フレームのうち **55.2% でボールが Human より奥**になっていた
  - 修正: proxy による位置・スケール上書きを廃止し、Else も Human/Animal と同じ `anchorZ` + bbox 経路に統一。sidecar 読み込みと `showOtherProxyBoxes` のデバッグ表示は debug 用途として残置
  - 詳細と数値は [bundle-placement.md](../../bundle-placement.md) の「NG パターン: `source/other_object_proxies.json` を配置に使う」に記録

## 発表で強調するポイント

- `source/*` を runtime 配置に使わないという鉄則は方針の問題ではなく、**単位系が runtime と揃っていない**という実害を伴う。しかも sidecar の値域（0.26〜0.91）が偶然 runtime の配置レンジ（0.69〜0.78 m）と近いため、「それらしく配置されるが前後だけ壊れる」という気づきにくい壊れ方をしていた
- 「bundle が悪いのか Unity が悪いのか」は `meta.bin` を直接パースして両者の深度を全フレーム比較することで切り分けた

## 残課題

- **深度レンジの圧縮**（未修正）: `anchorZ` 経路に統一しても Human とボールの深度差は中央値 1.5 cm しかない。`PopoutRangeMeters = 0.35f` に 0..1 の正規化深度全体を押し込んでおり、実際に使われる `z01` は 0.58〜0.90 のみなので有効レンジは約 11 cm。Human の胴体の厚み（20〜30 cm）に対して不足している
- 根本には「`depth_npz` はシーン全体で正規化された相対深度なので絶対距離を復元できない」という構造的制約がある。bundle 側で metric depth または depth のスケール・シフト係数を `manifest.json` に載せるのが本筋
- CC-BY-4.0 モデル（ディーゼル機関車）のクレジット表示が未対応（7/17 から継続）
