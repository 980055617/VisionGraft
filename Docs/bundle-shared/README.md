# bundle 共有ノート（生成側 ⇄ 利用側）

`.svb` bundle を**作る側**（Python プロジェクト）と**使う側**（Unity / VisionGraft）で共有するノート。
両プロジェクトに**同じ内容**を置き、更新のたびに手でコピーして同期する。

## このフォルダの使い方

**この `bundle-shared/` フォルダごとコピーして相手に渡す。** 中のファイルは全部まとめて 1 セット。

```
docs/bundle-shared/
├─ README.md                        ← 索引（使い方・同期ログ・課題一覧・データ契約）
├─ D-004-anchor-z-accuracy.md       ← 進行中の課題（1 課題 1 ファイル）
├─ D-009-animal-anchor-instability.md  ← 起票のみ・双方とも着手しない（記録用）
├─ archive/                         ← 解決・棄却した課題（読むだけ。追記しない）
│  ├─ D-001-depth-drift.md
│  ├─ D-002-inpaint-bypass.md
│  ├─ D-003-ball-depth-order.md
│  ├─ D-006-animal-bbox-anchor.md
│  ├─ D-005-depth-sampling-window.md
│  ├─ D-007-animer-joint-mapping.md
│  └─ D-008-anchor-z-quantization.md
├─ bundle_depth_check.py            ← 検証ツール（依存なし・単一ファイル）
├─ anchor_quality_check.py          ← anchor_z の抽出品質チェック（D-005 の裏付けを再現）
├─ anchor_z_order_check.py          ← 同一フレーム内の前後関係の集計（D-008）
├─ recommended_bundles.json         ← 各 clip の推奨 .svb と sha256・`buildParams`（機械可読）
├─ anchor_bbox_consistency_check.py ← bbox と `anchor_z` が食い違う区間の検出（D-004）
├─ train_depth_order.py             ← 1 フレームの配置を runtime と同じ式で再現（D-008）
└─ placement_depth.py               ← `anchor_z` → 配置深度（m）の移植（D-008 / D-004）
```

1. **両方のリポジトリの同じ場所に、フォルダごと同じ内容で置く**（Unity 側: `docs/bundle-shared/`）
2. 片方で更新したら、**フォルダごとコピーして**もう片方に上書きする
3. 貼ったら「同期ログ」に 1 行足す。**これを忘れると、どちらが新しいか分からなくなる**
4. **追記のみ。既存の記述は消さない。** 状況が変わったらステータスを更新し、経緯は残す
5. 各記述の頭に `[Unity側]` / `[bundle側]` と日付を付ける

**ファイルの分け方（2026-09-04 からこの方針）**

- **1 課題 1 ファイル。** 新しい課題を起票したら `D-0NN-<短い英語スラッグ>.md` を新規作成し、
  README の「課題一覧」に 1 行足す。README 本体には課題の中身を書かない
- **解決・棄却した課題は `archive/` に移す。** 移すときに課題一覧の行も「解決済み」の表へ移す。
  archive のファイルは**読むだけ**で、以後は追記しない（蒸し返すときは新しい課題を起票する）
- README は索引に徹する。ここが 150 行を超えたら、何かを別ファイルに出す合図
- **ツールを増やすとき**: このフォルダに入れて、上のツリーに 1 行足す。フォルダの外に置くと渡し漏れる

**衝突を避けるために**: 課題の詳細は「報告」欄と「回答」欄に分かれている。自分の側の欄だけに書けば、互いの更新が同じ行にぶつからない。相手の欄は空のまま残しておくこと。

もし両側が同時に編集してしまったら、**同期ログの最終行より後の追記だけ**を手で拾って混ぜる。
